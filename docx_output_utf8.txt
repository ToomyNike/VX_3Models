======= 计算机设计大赛思路：基于 APSIM 机理模型与微信小程序的全栈智慧农业平台.docx =======
云南省计算机大赛思路
云南高原特色咖啡“数字孪生”智能决策系统
—— 基于 APSIM机理模型与微信小程序的全栈智慧农业平台
一、 项目背景与建设目标
传统农业生产高度依赖人工经验，抗气候风险能力弱。当前市面上的农业管理系统多基于 PC 网页端，严重脱离了基层果农“没有电脑、下地忙”的现实工作场景。本项目致力于构建一个真正能够下沉到田间地头的数字孪生决策系统。
系统全面拥抱移动互联网生态，采用“微信小程序 + 轻量化 Python 后端”的架构。果农仅需在手机上完成极简的农事打卡，云端服务器即可悄无声息地驱动极其硬核的 APSIM 农业机理模型进行物理推演。最终，系统将晦涩的模型数据转化为直观的产量曲线与口语化的农技建议，直接推送到果农手机，打通智慧农业落地的“最后一公里”。
二、 总体技术路线与架构设计
为确保项目在有限周期内快速落地并具备极高的演示稳定性，本系统摒弃了臃肿的传统企业级架构，采用极其精简且高效的全栈技术方案：
前端交互层： 采用原生微信小程序框架。依托微信庞大的生态基础，实现果农的“免安装、即开即用”。在数据可视化方面，引入 ECharts 微信小程序版（echarts-for-weixin），在移动端流畅渲染动态折线图与指标面板。
后端接口层： 采用Flask 微框架构建 RESTful API 服务。Flask 的轻量化特性极大地降低了接口开发与环境配置的成本，主要负责接收小程序传来的 JSON 数据，并调度底层的计算引擎。
机理计算层： 系统直接在 Windows 环境（或 WSL）下运行。后端 Flask 接收到请求后，利用 Python 内置模块读写 APSIM 的 .apsimx 配置文件，并使用 subprocess 子进程直接调用 Windows 版 APSIM 的核心执行程序 Models.exe，实现无图形界面的静默推演。
数据与智能层： 全量采用 Python 原生支持的 SQLite 本地文件数据库。系统中仅存在两个极轻量的 .db 文件，一个用于存储果农账号与基础信息，另一个直接承接 APSIM 引擎模拟完毕自动生成的产量结果数据。此外，后端接入 千问、DeepSeek 或 Kimi 等大语言模型 API，充当智能农技顾问（后期和咖啡知识库大模型结合）。
三、 核心数据流转与人机交互机制
为了不增加果农的操作负担，系统对底层数十项复杂的农业物理参数进行了“黑盒封装”，果农在小程序端只需进行最符合直觉的简单交互。完整的数据流转机制如下：
果农上传的数据：
果农在使用初期仅需进行一次建园初始化，填写咖啡园的实际亩数、咖啡树大致树龄，并通过小程序一键获取所在果园的经纬度定位（用于后端自动匹配气象数据）。在日常巡园时，果农只需像发朋友圈一样进行“农事打卡”。例如完成浇水后，选择日期并输入大致水量（毫米或立方）；完成施肥后，选择日期、肥料类型（如尿素）并输入公斤数。这些简单的数字将通过 Flask 接口直接映射修改底层 APSIM 的运作参数。
果农在小程序端输入数据清单
此外，后端计算输入数据：
气象数据 (Weather)：每日最高温、最低温、降雨量、辐射。全部由 Python 定时抓取气象 API 或果园 IoT 气象站写入 .met 文件。
土壤水热与本底 (Physical, Chemical)：土壤容重、田间持水量、萎蔫点、初始氮磷钾。这些由你用当地红壤数据在 .apsimx 模板里写死。
作物遗传 (Cultivar)：咖啡的积温要求、光能利用率、最大根深。模板写死。
小程序输出的数据：
经过后端的秒级运算，果农将在小程序首页直观获取三大维度的数字反馈。首先是当前状态大字报，显示当前咖啡所处的精准生育阶段及预计距离采收的天数。其次是 ECharts 驱动的产量预测曲线，果农可以清晰看到：随着今天的浇水或施肥，原本预测的 1200 公斤最终产量曲线上扬到了 1350 公斤。最后是大模型生成的智能农事建议，系统会将“土壤水分逼近萎蔫下限”等枯燥警告，转化为诸如“李老板，模型测算未来一周果园极度缺水，为保住产量，建议明天紧急滴灌”的口语化文字。

四、 敏捷研发计划与 AI 辅助开发策略
本项目的核心系统（MVP版本）规划在 1 周内极速完成开发与联调，这主要得益于全流程引入Antiogracity编程智能体的辅助。
在开发的前两天，将集中攻坚核心引擎的自动化。由开发人员向 AI 描述业务逻辑，AI 自动生成 Python 脚本以实现对 .apsimx 文件的精确解析、变量替换、Models.exe 的命令行驱动以及 SQLite 结果库的 SQL 读取。第三天利用 AI 快速生成 Flask 的数据接收与返回路由，打通后端。
第四至第五天转战微信开发者工具，由 AI 辅助快速生成带有日期选择器和输入框的表单页面，并植入 ECharts 组件完成静态图表展示。最后两日进行局域网内的前后端接口联调，修复通信报错，并接入大语言模型 API，完成提示词工程的封装，最终输出可供答辩的完整演示系统。
五、 竞赛核心竞争优势
首先是技术壁垒，项目并未停留在常规的信息管理系统层面，而是引入了业内顶尖的机理模型作为内核，实现了基于物理与生物方程的严谨推演。其次是极高的场景契合度，微信小程序叠加 Windows 服务器与 SQLite 的轻量化组合，摒弃了华而不实的重型技术，契合农业领域尤其是下沉市场的真实落地需求。最后是前沿的 AI 融合应用，通过将机理模型的精准数据与大语言模型的文字生成能力相结合，打造了典型的 Agentic（智能体）工作流，生动诠释了“智慧农业数字化转型”的深刻内涵。

2.2 HYDRUS 在系统中的角色
HYDRUS 不负责产量预测，主要负责解释土壤水分过程。
HYDRUS 需要回答的问题：
1. 水进入土壤了吗？
2. 水进入多深？
3. 主要根区有没有吸到水？
4. 现在是真缺水，还是只是表层干？
5. 是否需要灌溉？
6. 灌溉后是否会出现深层渗漏？

第八章 最终系统表述
本系统采用微信小程序作为果农入口，Flask 作为本地模型调度后端，APSIM 作为咖啡生长与产量预测主模型，HYDRUS 作为土壤水分与根系吸水解释模型，BEPS-Lite 作为区域生态过程扩展模型。三类模型统一输出 JSON，由后端融合后返回小程序，最终形成果农能理解的 what、how、why 农技建议。
